Functional Requirements Document

1. Authentication

FR-AUTH-01: Sign Up

  • User provides email and password (min 6 chars)
  • Supabase creates auth.users record
  • DB trigger fires: inserts row into credits with balance = 3
  • User is auto signed-in after registration
  • Redirect to main app

FR-AUTH-02: Sign In

  • Email + password validated by Supabase
  • JWT returned and stored in Supabase client session
  • App restores CV profile and credit balance from DB

FR-AUTH-03: Forgot Password

  • User enters email on Forgot Password tab in AuthModal
  • Supabase sends reset email with magic link to /reset-password
  • Reset page listens for PASSWORD_RECOVERY auth event
  • User enters new password (min 6 chars, confirmed twice)
  • On success: redirect to app after 2.5 seconds

FR-AUTH-04: Session Persistence

  • JWT stored in browser by Supabase client automatically
  • On page load: supabase.auth.getSession() restores session
  • If no session: Landing Page shown
  • On sign out: all local state cleared, Landing Page shown

2. CV Parsing

FR-CV-01: File Upload

  • Accepts: PDF, DOCX, TXT — max 10MB
  • Text extracted: PyPDF2 for PDF, python-docx for DOCX
  • Minimum 100 characters required to proceed

FR-CV-02: AI Parsing (Haiku 4.5)

  • Fields extracted: name, email, phone, linkedin, title, location, years_exp, seniority, domain, skills (up to 25), summary (2–3 sentences), initials
  • Null returned for any field not found — no hallucination
  • Raw CV text stored (up to 12,000 chars) for downstream use

FR-CV-03: Profile Storage

  • Saved to cv_profiles table scoped to user_id
  • Raw text stored in sessionStorage — survives refresh, clears on tab close
  • Profile restored from DB on every login via GET /api/cv/profile
  • Multiple uploads allowed — each creates a new row; latest used

3. JD Evaluation

FR-EVAL-01: Input Validation

  • JD text minimum 50 characters
  • Role name and company name optional — used for display only

FR-EVAL-02: Credit Check

  • Balance checked before API call
  • If balance = 0: 402 returned, payment modal triggered on frontend
  • 1 credit deducted atomically before API call
  • Usage logged to usage_log with action = "jd_evaluate"

FR-EVAL-03: AI Evaluation (Sonnet 4.6, prompt-cached)

Returns JSON with: role_summary, company_signals, cv_match (matched_skills, match_summary), gaps (skill, importance, mitigation), grade (A–F), grade_reasoning, salary_range (min, max, currency, confidence, reasoning), red_flags, green_flags, recommended_action, recommended_action_reason

FR-EVAL-04: Grading Rules

GradeCriteria
A80%+ skill match, domain aligned, right seniority, no critical red flags
B60–79% match, 1–2 fillable gaps, minor domain shift
C40–59% match, meaningful domain change, 2+ critical gaps
D<40% match, wrong domain, multiple critical gaps
FFundamentally different field, would be ATS-filtered out

FR-EVAL-05: Persistence

  • Evaluation result, JD text, role, company stored in localStorage
  • Survives browser refresh — user does not lose evaluation on reload
  • Evaluation also saved to jd_evaluations table in DB
  • Download as HTML report — open in browser → Print → Save as PDF

4. CV Tailoring

FR-TAILOR-01: Prerequisites

  • CV must be parsed (profile exists)
  • Raw CV text must be available (sessionStorage)
  • JD must be evaluated (evalJdText in state, min 50 chars)
  • All three shown as checklist — button disabled until all green

FR-TAILOR-02: AI Output (Sonnet 4.6)

Returns JSON with: professional_summary, skills (array), experience (array of company/title/duration/bullets), technical_projects, certifications, education, application_briefing (lead_with, mirror_language, downplay, add_if_possible)

FR-TAILOR-03: DOCX Generation

  • Generated entirely in browser using docx npm package — no server round-trip
  • Sections: Name, Title + Location, Contact (email | phone | linkedin), Divider, Professional Summary, Key Skills, Professional Experience, Technical Projects (if any), Certifications, Education
  • Contact line uses real values from parsed profile — shows placeholder only if fields are null
  • Downloaded as: {Name}-tailored-CV-{date}.docx

FR-TAILOR-04: State Management

  • Result lifted to SeekerMode — survives tab switching
  • No "Tailor again" button — prevents accidental credit spend
  • To retailor: user must re-upload CV (intentional friction)

5. Interview Prep

FR-INTERVIEW-01: Prerequisites

  • Same as CV Tailoring — CV parsed + raw text available + JD evaluated
  • Checklist shown identical to Tailor CV tab

FR-INTERVIEW-02: AI Output (Sonnet 4.6)

Returns JSON with: behavioral_questions (5 items, each with question, why_asked, star_answer {situation/task/action/result}, key_phrases), red_flags (2 items, each with topic, likely_question, how_to_frame), questions_to_ask (4 items, each with question, why_it_works)

FR-INTERVIEW-03: Credit Refund on Failure

  • If AI call fails or returns unparseable JSON: credit is automatically refunded
  • Error message shown: "your credit has been refunded"
  • Prevents users being charged for backend errors

FR-INTERVIEW-04: Export

  • Download as HTML file — clean formatted report
  • Includes: all 5 STAR cards, red flags, questions to ask, Mock Interview coming soon banner
  • User opens in browser → Ctrl+P → Save as PDF

6. Payment Flow

FR-PAY-01: Order Creation

  • POST /api/payments/create-order with pack_id
  • Returns Razorpay order_id, amount, currency
  • 503 if RAZORPAY_KEY_SECRET env var not set

FR-PAY-02: Payment Verification

  • Frontend sends: razorpay_order_id, razorpay_payment_id, razorpay_signature
  • Backend verifies HMAC-SHA256 signature before crediting
  • On success: credits added to credits table, logged to payment_log
  • Frontend updates credit balance display immediately

7. Admin Dashboard

FR-ADMIN-01: Access Control

  • Admin user ID hardcoded in both frontend and backend middleware
  • Frontend: non-admin sees "Not found" at /admin
  • Backend: all /api/admin/* endpoints return 403 for non-admin JWT

FR-ADMIN-02: Stats

  • Total users, active (30d), stale count
  • Credits: total issued, used, remaining
  • Usage: last 7d, last 30d, breakdown by action
  • Estimated Anthropic spend (from usage log, not live API balance)
  • Per-user table: email, balance, lifetime used, active/stale status, last seen

FR-ADMIN-03: Gift Credits

  • Dropdown of all registered users (email + user_id)
  • Select amount: 2, 5, 10, 15, 20, 30 credits
  • Optional note field
  • Credits added instantly, usage_log entry created with action = "admin_gift"

8. Rate Limiting

  • slowapi (10 requests/minute) applied to: POST /api/evaluate/evaluate-jd, POST /api/tailor/tailor-cv, POST /api/interview/prep
  • Limit is per IP address
  • 429 returned on exceeded limit
